CONTEXT
- Rule R7 of `docs/STATE-TRANSFER-REFACTOR.md` specifies that outbound state publication must be wake-driven on `SessionState.version` changes, comparing the latest snapshot to the last-acked snapshot using `_diff_field_groups` from `resources/lib/session_state.py`.
- `resources/lib/session_state.py` defines `FIELD_GROUPS` partition: `identity` (`video_id`, `list_id`, `current_index`), `playback` (`state`, `media_time_ms`, `duration_ms`), `volume` (`volume`, `muted`), and `lane` (`lane`).
- `LoungeSession.report_state` currently enqueues into `_report_queue` with a per-tag coalescing dictionary `_coalesced_tags` and an explicit exception `if tag == "nowPlaying": return True`, which Rule R7 requires removing.
- `LoungeSession._drain_loop` batches pending items up to 4 or until queue empty, serializes via `_post_raw(path, data)`, and assigns `ofs` sequentially.
- In `LoungeSession.connect`, the initial handshake assigns `self._ofs = 0` and increments `ofs` on each frame transmitted during handshake; outbound RPC calls via `_post_raw` send `req0__sc=<action>` and query param `ofs=<int>` on `POST /bc/bind`.
- In `LoungeSession`, `_ofs` is currently modified both during `connect()` and in `_drain_loop()` without a dedicated `_ofs_lock`, whereas Rule R7 mandates that `ofs` sequence progression per channel be strictly monotonic under `_ofs_lock` shared with the handshake path.
- In `resources/lib/player_bridge.py`, `PlaybackMonitor._tick` currently runs periodic polling every ~0.5s–1.0s and makes ad-hoc calls to `self.owner.apply(...)` and `session.report_state(...)` or `session.report_now_playing(...)`.
- `LoungeSession.report_now_playing` formats YouTube Lounge RPC actions `nowPlaying` (with params `videoId`, `currentTime`, `duration`, `state`, `cpn`) and `nowPlayingPlaylist` (with `listId`, `currentIndex`, `videoIds`).
- `LoungeSession.report_state_change` formats `onStateChange` (`state`), `LoungeSession.report_volume` formats `onVolumeChanged` (`volume`, `muted`).
- When an HTTP post fails in `_drain_loop`, `_post_raw` catches `URLError`/`HTTPError` and returns `False`; Rule R7 requires leaving the state version dirty so the subsequent cycle republishes the latest absolute state rather than retrying dropped intermediate states.
- Emulator scenarios in `emulator/scenarios/` (e.g. `test_duration_reporting.py`, `test_remote_control.py`, `test_dup_relay_burst.py`) check `server.REPORTS` for `nowPlaying`, `onStateChange`, and `onVolumeChanged` actions received from the addon.
- Emulator's `LoungeServer` frames parser in `emulator/lounge_server/` expects standard bind RPC format where `req0__sc` contains the command name and `req0_<param>` contains arguments.
- The full-snapshot heartbeat running at <= 1 Hz must emit the complete active state snapshot to Lounge distinctly marked (e.g. `heartbeat=true` in logs) to enable client crash-recovery without registering as normal state change traffic.
- Intermediate `SessionState` updates that occur while an HTTP transmission is in flight must be superseded: the next dispatch must diff the newest active snapshot against the last successfully acknowledged snapshot, bypassing any intermediate versions.
