GOAL
State changes across the Kodi YouTube Lounge session are unified under a pure, idempotent reduction model in `resources/lib/session_state.py` per Rule R3 of `docs/STATE-TRANSFER-REFACTOR.md`. Direct field writes to session state are eliminated; every change is dispatched as an explicit first-class `Event` through `reduce(state: SessionState, event: Event) -> SessionState` invoked via `StateOwner.apply`. The reducer contains no side effects, no I/O, and no wall-clock reads, ensuring that replaying duplicate events (such as duplicate relay bursts) produces the identical state and leaves `version` unchanged. Every accepted state change increments the monotonic `version` counter and emits exactly one log line matching the debug contract format `state v<N> <event> -> <changed field groups> (<source>)`, verified by runnable unit tests in `tests/test_session_state.py`.

- `test_addon.py` automatically discovers and executes the full suite in `tests/test_session_state.py` via `unittest.defaultTestLoader.loadTestsFromName("tests.test_session_state")`.
- `reduce(state: SessionState, event: Event) -> SessionState` enforces idempotence by returning the existing `state` instance unmodified (`self.assertIs(s_dup, s)`) when incoming event data matches current state; duplicate/no-op reductions must not increment `version` and must completely suppress emission of the reduction log line.
- The debug contract logger is `logging.getLogger("ytlounge.state")` at `logging.INFO`, formatting log lines strictly as `state v<N> <event> -> <changed field groups> (<source>)` where event names use camelCase via `Event.event_name` (e.g., `setPlaylist`, `kodiStateObserved`).
- Field groups for log diffing are strictly partitioned into four categories: `identity` (`list_id`, `playlist`, `current_index`, `current_video_id`, `cpn`), `playback` (`play_state`, `position`, `duration`), `volume` (`volume`), and `lane` (`lane`).
- `reduce` must remain completely deterministic and side-effect free: random CPN generation (`generate_cpn()` via `secrets`) must never be invoked inside `reduce`; CPNs during transitions must either use `event.cpn`, preserve `state.cpn`, or derive deterministically (e.g., `"cpn_" + next_vid`).
- Unrecognized or unhandled event classes passed to `reduce` must return `state` untouched without logging or raising exceptions, as asserted in `test_version_monotonicity`.
- `StateOwner.apply(event)` wraps `reduce` and executes `self._on_apply(new_state)` inside a `try/except Exception: pass` block so that persistence hook errors in `player_bridge.py` cannot abort or corrupt state reduction.
- `StateOwner` and `SessionState` provide legacy read-only aliases (`state` mapping to `play_state`, `theme` and `current_theme` mapping to `lane`) that existing callers in `resources/lib/player_bridge.py` and `emulator/kodi_stub` depend on.
- All four writer paths in `resources/lib/player_bridge.py` already route mutations through `self.owner.apply(Event(...))` and access state exclusively via read-only properties delegating to `self.owner`.
- Backward compatibility aliases required across writer paths include `PlayVideoEvent = PlayEvent`, `StopEvent = StopVideoEvent`, and `ResolverResolvedEvent = ResolverCompletedEvent`.
- `SeekToEvent` must support both `seconds` and `position` keyword arguments in its constructor, with `__post_init__` harmonizing them so both attributes remain accessible.
- Repair-path events that do not affect the 11 `SessionState` fields (such as `QueueTitlePatchedEvent` and `ResolverSupersededEvent`) must return `state` unchanged without bumping `version` or emitting reduction logs.
